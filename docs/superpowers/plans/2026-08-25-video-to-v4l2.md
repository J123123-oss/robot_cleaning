# Video To V4L2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone ROS package command that replays a recorded video into `/dev/video0` through `v4l2loopback`, allowing the existing `camera_publisher_node` to test the real V4L2 input path.

**Architecture:** Keep video injection separate from `camera_publisher_node`. The new Python CLI validates the input and playback settings, creates `/dev/video0` by loading `v4l2loopback` when needed, and launches `ffmpeg` with a fixed-size `yuyv422` V4L2 output. The video is scaled while preserving aspect ratio and center-cropped to the requested dimensions, so no blank border or non-uniform stretch is introduced. The existing camera node remains the consumer of `/dev/video0` and is unchanged.

**Tech Stack:** Python 3, `argparse`, `subprocess`, `ffmpeg`, Linux `modprobe`, `v4l2loopback`, ROS2 `ament_python` entry point, pytest.

### Task 2: Implement the V4L2 video replay utility

**Files:**
- Modify: `src/rtk_nav/rtk_nav/video_to_v4l2.py`

- [x] **Step 1: Add argument parsing and validation**

  Implemented `parse_args` with `--video` required, `--device` defaulting to `/dev/video0`, `--width` defaulting to `640`, `--height` defaulting to `480`, `--fps` defaulting to `30`, `--loop` as a boolean flag, and `--no-create-device` to disable automatic module loading. Non-positive dimensions/FPS and odd widths are rejected through `argparse.ArgumentTypeError`.

- [x] **Step 2: Add deterministic ffmpeg command construction**

  Implement `build_ffmpeg_command(args)` returning an argument list equivalent to:

  ```text
  ffmpeg -hide_banner -loglevel warning -re [-stream_loop -1] -i VIDEO
    -vf scale=WIDTH:HEIGHT:force_original_aspect_ratio=increase,
        crop=WIDTH:HEIGHT:(iw-ow)/2:(ih-oh)/2,
        fps=FPS,format=yuyv422
    -f v4l2 -pix_fmt yuyv422 -s WIDTHxHEIGHT -r FPS DEVICE
  ```

  Use a list passed to `subprocess.run`/`subprocess.Popen`; do not use `shell=True`.

- [x] **Step 3: Add dependency and device checks**

  Implement `ensure_v4l2_device(device)` so it:
  - returns immediately when the device already exists;
  - checks for `modprobe` and `v4l2loopback` module availability;
  - invokes `modprobe v4l2loopback devices=1 video_nr=0 card_label=RecordedVideo exclusive_caps=1` through `sudo` when not running as root;
  - waits briefly for the device node and raises a clear `RuntimeError` containing the required `apt` command if creation fails.

  The default module load is only for `/dev/video0`; for another device path, report that the corresponding loopback device must already exist rather than guessing a device number.

- [x] **Step 4: Add the process lifecycle**

  Implement `main` to check the video file and `ffmpeg`, create/check the V4L2 device, start the ffmpeg process, forward Ctrl-C, and return ffmpeg's exit code. Log the exact device and format so the next command can start `camera_publisher_node`.
