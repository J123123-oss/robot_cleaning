# 设备总电流与滚刷堵转保护设计

## 意图
运行中的机器人出现持续高负载时，使用电池总电流和 AIMOTOR 滚刷电机的实际电流及时停车，进入 `HOLD`，通过 `/robot_state` 上报故障位和电机故障信息，避免设备持续受阻。

## 范围与约束
- 保留电池总电流保护：绝对值超过 4.0 A 且持续 5.0 s 才触发；低于等于阈值或设备没有运动指令时清零计时。
- AIMOTOR 对象 `6078:00` 为实际电流 `Int16`，单位 `0.01 A`。只对配置中的滚刷电机（节点 ID 3、4）做独立超流计时，默认阈值 4.0 A、持续 5.0 s，并允许 ROS 参数调整。
- 实际电流由 CANopen SDO 后台查询；每个样本携带数据新鲜度，过期样本不参与滚刷保护。
- 当前故障码通过 `603F:00` 查询；故障历史 `1003:01` 的低 16 位为 CiA402 故障码、高 16 位为对应厂家故障码。查询使用只读对象，不写历史选择寄存器。
- `/robot_state` 的 `motor_fault` 保持现有按电机顺序排列的 CiA402 故障码数组；增加 `motor_fault_details` 提供节点 ID、厂家故障码和实际电流，避免破坏既有字段类型。
- 电池总电流或任一活动滚刷持续超限时，沿用 `ERROR_TOTAL_OVERCURRENT = 256`、清零轮子和滚刷速度、切换 `HOLD`、保留使能并立即发布状态；保护状态记录触发来源、电流和电机 ID。
- 滚刷电流超出阈值时记录限频异常日志；达到持续时间后写入堵转保护日志并触发与电池总电流相同的锁存停车流程。
- 保护锁存后进入 `HOLD`；显式 `ENABLE`、`DISABLE` 或重新进入 `AUTO_CLEANING` 都可作为人工确认清除锁存，其中 `AUTO_CLEANING` 清除后恢复清扫。

## 实现边界
- 修改 AIMOTOR CANopen 驱动、`motor_control` 状态节点和保护检测器；MQTT 桥接继续转发现有 `/robot_state` JSON。
- 保持旧版 `motor_feedback` 五字段数据读取兼容；新版反馈在末尾追加实际电流与样本年龄。
- 不自动清除或改写厂家故障历史；现有 CiA402 故障复位行为保持不变。

## 验证
- 覆盖 SDO 电流缩放、603F 当前故障码、1003 历史组合码、滚刷超流计时/停车、MQTT 状态字段和旧反馈格式兼容。
- 运行 `motor_control` 相关 pytest、Python 语法检查及 `git diff --check`。
