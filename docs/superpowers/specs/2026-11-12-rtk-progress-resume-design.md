# RTK 清扫进度持久化与 RESUME 设计

## 目标

保存当前清扫路线、路线 ID、航点索引、区域和导航阶段。服务重启后默认仍从启动参数指定路线的第一个航点开始；只有收到 MQTT `{"command":"RESUME"}` 才加载上次保存的路线和航点进度。

## 范围

- `rtk_nav` 负责写入和读取进度快照，因为它拥有真实航点推进状态。
- `motor_control` 只解析 MQTT `RESUME`，通过 ROS 话题请求 `rtk_nav` 恢复。
- 恢复只恢复导航上下文，不自动切换电机状态或启动清扫。
- 路线完成后删除快照，避免下一次任务误恢复已完成路线。

## 快照

快照保存于启动路线目录下的 `.rtk_nav_progress.json`，字段包括版本、路线 ID、路线文件绝对路径、当前航点索引、区域名、导航状态、目标航点和更新时间。写入采用临时文件加原子替换，损坏或字段无效时忽略并继续默认启动。

## 恢复流程

1. MQTT 收到 `RESUME`，`motor_control` 发布 `/rtk/resume_progress`。
2. `rtk_nav` 读取快照，校验路线文件、同名围栏和航点索引。
3. 必要时加载快照中的路线，设置当前航点和导航状态，保持停止。
4. 后续由操作员手动执行 `ENABLE`，再切换到 `AUTO_CLEANING`；恢复入口仍经过现有围栏门控。

## 不恢复的情况

- 没有快照、快照损坏、路线不存在、航点索引越界或围栏文件缺失。
- 当前正在 AUTO_CLEANING 或进出仓流程中。
- 路线任务已经完成并已清除快照。

## 方案取舍

在 `motor_control` 保存状态会依赖 MQTT 状态发布时序，可能落后于真实航点；在 `rtk_nav` 保存可直接覆盖航点切换、区域跳转和路线切换，因此采用 `rtk_nav` 单点持久化。
