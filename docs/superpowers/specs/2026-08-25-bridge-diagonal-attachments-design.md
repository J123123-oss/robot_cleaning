# 桥架与清扫区域斜向补接设计

## 目标

调整 `rtk_nav.auto_path_planner` 生成的桥架过渡路径：桥架进入或离开矩形清扫区域时，区域内补接优先使用起终点之间的一条斜向直线，消除当前由两段直角短路径组成的 L 形补接。

本次调整只影响桥架端点与清扫段之间的两类补接：

- 源区域最后一条清扫段的终点 -> 桥架起点；
- 桥架终点 -> 目标区域第一条清扫段的起点。

桥架自身的 RTK 轨迹、清扫段之间的内部连接、区域边界和输出格式保持不变。

## 方案

规划器在局部米制坐标中处理桥架端点补接。对每个补接请求按以下顺序选择路径：

1. 检查起点和终点仍位于对应区域的允许几何内；
2. 检查起点到终点的单段直线是否完全位于允许几何内，并且长度不超过 `max_connector`；
3. 若检查通过，输出两个点组成的一条斜向或直线补接；
4. 若直线穿过区域外部、孔洞或超长，沿用现有安全正交连接器，继续寻找经过边界节点的可行路径；
5. 两种路径都不可行时，保持现有错误行为并报告连接失败。

安全检查仍复用 `_line_is_allowed_region`，因此斜线不能穿过区域边界、孔洞或其他禁行区域。桥架端点校验继续使用未应用 `edge_distance` 的原始外围边界，避免边缘缩进影响桥架入口；斜向补接只作为区域内的行驶路径，不扩大允许区域。

## 数据流与接口

不新增地图字段和命令行参数。`plan_route` 在处理显式 connector 时，分别为桥架源端和目标端调用一个“桥架补接连接器”选择函数。该函数先尝试直线，再调用现有 `_find_region_connector` 作为回退。

输出仍使用普通 `Segment(kind="connector")`：

- 区域内桥架补接保留对应 `region_id`；
- 桥架实线路径保留 `connector_id`、`from_region` 和 `to_region`；
- 直线补接的长度和 GeoJSON 表示由现有序列化逻辑生成。

## 边界条件与错误处理

- 起点或终点在对应区域外时，继续立即报错；
- 直线只要有一段越过区域外或孔洞，就不能使用；
- 起终点重合时仍输出零长度单点连接，不额外生成线段；
- 直线长度超过 `max_connector` 时回退正交连接器；
- 回退路径也超出 `max_connector` 或不存在时，沿用现有 `PlanningError`。

## 测试设计

新增和调整单元测试覆盖：

- 简单矩形桥架入口和出口优先生成恰好两个点的斜向连接；
- 斜线穿过孔洞时回退为安全正交路径；
- 现有 E9/E10/E11 和 E12/E13/E14 地图仍能生成路线，并保持桥架端点及顺序不变；
- 内部清扫连接仍为正交路径；
- JSON 和 GeoJSON 序列化继续包含正确的 connector 属性和长度。
