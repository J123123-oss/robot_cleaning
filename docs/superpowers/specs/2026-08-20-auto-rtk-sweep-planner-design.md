# RTK Auto 扫描式路径规划设计

## 目标

新增一个 `auto` 路径规划模式，使用一次外围 RTK 轨迹和少量方向参考轨迹，自动生成多块相连矩形区域的连续清扫路线。自动模式不要求每个矩形单独标定角点，也不要求为相邻矩形单独配置桥接区域。

## 范围与非目标

本次只实现离线路径生成，不修改 `rtk_nav.py` 的导航状态机和现有手工 YAML 模式。自动模式输出新的 JSON/GeoJSON 文件，不兼容旧的 `.txt` 航点格式。

本次不从图片自动识别光伏板，不做 SLAM，不做全局 TSP 优化。内部无法通行的区域由可选的 `no_go` 多边形提供；如果路线无法安全连接，规划器必须报错，不得生成一条可能穿越禁行区的直线。

## 输入格式

自动模式读取一个 JSON 文件：

```json
{
  "boundary": [[110.6474, 35.6060], [110.6480, 35.6060], [110.6480, 35.6052]],
  "guides": [
    [[110.6475, 35.6053], [110.6475, 35.6059]]
  ],
  "no_go": [],
  "start": [110.6475, 35.6053]
}
```

- 坐标顺序固定为 `[经度, 纬度]`。
- `boundary` 是可清扫总区域的外轮廓，首尾可以重复，也可以不重复，加载时自动闭合。
- `guides` 是一条或多条方向参考轨迹；规划器使用其长轴估计统一清扫方向。
- `no_go` 是可选的内部禁行多边形列表。
- `start` 可选；缺省时使用第一条 guide 的第一个点附近作为规划起点。

命令行参数：

```text
--input             输入 JSON 文件，必选
--output            输出路线 JSON，必选
--sweep-spacing     相邻清扫线间距，默认 1.0 米
--edge-clearance    清扫线端点和区域边界的安全距离，默认 0.3 米
--max-connector     允许的最大连接距离，默认 8.0 米
```

## 核心算法

### 1. 局部米制坐标

以外围边界第一个点为原点，使用小范围等距投影将经纬度转换为本地米制坐标。该项目的建图范围是屋顶/场站级别，使用经纬度差乘以纬度修正系数足以支持路径生成，同时避免给桌面工具引入额外的 UTM 依赖。输出时再转换回经纬度。

### 2. 主方向估计

对每条 guide 的首尾向量计算无方向角，把角度映射到 `[0, pi)` 后用双角度平均估计主方向。这样即使不同 guide 的行驶方向相反，也能得到相同的清扫轴。

### 3. 扫描线生成

把边界和禁行区变换到“主方向为 X 轴”的局部坐标系。沿法向 Y 轴按 `sweep_spacing` 生成扫描线。扫描线与外边界、禁行多边形的所有边求交，按交点排序并成对组合为可清扫区间；再对区间端点做 `edge_clearance` 裁剪。

该方法直接处理一个凹多边形或多个孔洞，不需要先把区域拆成多个矩形，因此相邻矩形的重叠部分不会被重复生成。

### 4. 连续路径与连接

清扫区间按照扫描线顺序生成蛇形路线。相邻清扫线段之间优先使用直线连接；如果直线不在允许区域内，再尝试两个轴对齐的折线路径。每条连接线均通过采样点检查：必须位于外围边界内，且不能进入 `no_go`。

如果没有满足安全条件的连接线，规划器抛出明确错误并指出两个区间的索引。它不会自动插入一条未经验证的桥接直线。

## 输出格式

路线 JSON 使用顺序段表示：

```json
{
  "format": "rtk_auto_route_v1",
  "axis_angle_deg": 90.0,
  "segments": [
    {"kind": "coverage", "points": [[110.0, 35.0], [110.0, 35.1]]},
    {"kind": "connector", "points": [[110.0, 35.1], [110.01, 35.1]]}
  ],
  "metrics": {
    "coverage_segments": 10,
    "connector_segments": 9,
    "total_length_m": 123.4,
    "max_connector_length_m": 1.2
  }
}
```

同时输出一个 GeoJSON `FeatureCollection`，每条清扫段和连接段分别作为 `LineString`，便于 QGIS 或网页检查。路线 JSON 是自动模式的主输出，GeoJSON 是可视化副产物。

## 代码边界

- 新增 `src/rtk_nav/rtk_nav/auto_path_planner.py`：数据校验、坐标投影、方向估计、扫描线、连接检查、JSON/GeoJSON 输出和命令行入口。

- 新增 `src/rtk_nav/test/test_auto_path_planner.py`：纯 Python 契约和几何测试。
- 不修改 `full_path_planner_dense.py`、`rtk_nav.py` 或现有 YAML 配置。

## 错误处理

输入缺少 `boundary`、`guides`、有效点数不足、扫描间距非正、边界退化、起点不在可用区域或连接距离超过上限时，抛出 `PlanningError`，命令行返回非零状态并输出可读错误。

## 测试策略

测试覆盖：

1. JSON 输入校验和首尾自动闭合。
2. 相反方向 guide 得到相同主方向。
3. 简单矩形生成多条平行清扫段，且段数和方向正确。
4. 内部 `no_go` 会把扫描线分成两个区间，不生成穿越禁行区的连接。
5. 连接失败时抛出错误，而不是生成直线。
6. 输出 JSON/GeoJSON 包含 coverage、connector 和统计指标。

验证使用纯 Python AST、`py_compile` 和直接调用测试函数；如果 ROS2 工作环境提供 pytest，再运行对应 pytest 文件。
