# RTK 图纸仿射标定设计

## 目标

修复 RTK 点位查看器在图纸存在横纵比例差或轻微倾斜时的标定失败问题。三点及以上控制点使用二维仿射变换，允许 25、26、27 这类实际位置正确但不满足等比例相似变换的点组完成对齐。

两点结果只作为临时定位使用，页面必须明确提示不能据此判断方向和标定可信度。三点及以上结果继续显示控制点残差和 RMSE，RMSE 超过阈值时回退到近似摆放。

## 非目标

- 不引入透视单应变换。
- 不修改 RTK 采点文件和经纬度数据。
- 不把手动底图显示调整写入控制点像素坐标。
- 不改变点位数据的坐标系转换逻辑。

## 方案

当前实现拟合的是保持角度和比例的相似变换。25、26、27 的像素三角形与 UTM 三角形比例不一致时，相似变换只能折中，导致 RMSE 很大。两点时又会得到零残差，但东西方向由两点间很小的横向差决定，可能把西侧点映射到右侧。

改为拟合 UTM 到图纸像素的仿射变换：

```text
u = a * east + b * north + c
v = d * east + e * north + f
```

使用三个控制点时直接确定六个参数。超过三个控制点时使用最小二乘拟合，并以所有控制点的像素残差计算 RMSE。点位反算坐标和页面绘制统一使用同一仿射模型。

## 页面行为

- 少于 2 个控制点时显示未标定。
- 恰好 2 个控制点时允许绘制临时两点定位，但状态提示明确标记为“临时定位，至少需要 3 个控制点才能验证标定”。
- 三个及以上控制点时进入仿射标定。控制点不共线时才允许求解。
- 新增第三个及后续控制点时，先按已有模型计算交叉验证误差，再加入控制点。
- 控制点加入后，若仿射 RMSE 超过 20 px，页面回退到近似摆放并保留控制点列表，提示用户删除异常控制点。
- 导出 JSON 时保留现有控制点字段和视图字段，并增加模型类型字段，重新加载时按字段恢复仿射标定。
- 教程改为要求至少 3 个分布在图纸不同区域的控制点，并要求用独立的第 4 个点交叉验证。

## 验证标准

- 使用 25、26、27 的图纸像素位置时，仿射模型能将三个控制点残差降至浮点误差范围。
- 使用 25、26 两点时，页面不再显示“已标定”或 RMSE 0 px 的可信状态。
- 25、26 两点的临时模型仍能用于定位，但页面明确提示方向未经验证。
- 使用共线控制点时，页面提示无法求解，不生成有效仿射模型。
- 高 RMSE 控制点组继续回退近似摆放。
- 重新生成的 HTML 包含仿射标定代码、当前 20 条采点和内嵌 SVG。
- Python 语法检查、相关离线测试和 HTML JavaScript 语法检查通过。
