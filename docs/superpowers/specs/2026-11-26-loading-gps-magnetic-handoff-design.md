# 进仓寻 GPS 磁条接管设计

## 目标

进仓流程在 GPS 目标点附近进行航向微调时，如果已经检测到新鲜磁条，立即结束 GPS 寻点阶段并进入现有磁导航后退流程，避免低速微调打滑导致进仓卡滞。

## 现状与问题

`MotorControlNode` 在 `LOADING_NAV_TO_GPS`、`LOADING_TURN` 和位置恢复阶段只依赖 GPS 距离与 IMU 航向判定。即使磁条传感器已经检测到磁条，流程仍可能持续以很小的轮速微调，无法完成连续航向稳定计数。

## 方案

采用 GPS 阶段检测磁条并接管的方案。磁条原始采样在 GPS 相关阶段连续两帧非零后，下一次进仓定时器回调执行以下动作：

- 停止当前轮速。
- 初始化与正常角度调整完成后相同的磁导航后退阶段状态。
- 将 `loading_phase` 切换为 `LOADING_DIRECT_BACKWARD`。
- 继续使用现有磁条纠偏、后退计时和末端横向磁条完成判定。

单帧磁条信号不触发接管，零值采样或采样间隔超过 0.5 秒会清除连续计数。接管时最新原始采样必须不超过 0.5 秒；磁导航关闭或进仓暂停时不接管。计数只在 `LOADING_NAV_TO_GPS`、`LOADING_TURN` 和 `LOADING_POS_RECOVER` 阶段累积，避免复用旧状态或干扰已经进入磁导航后的流程。

## 范围

- 修改 `src/motor_control/motor_control/motor_control.py` 的进仓阶段状态和磁条采样计数。
- 为 GPS 阶段磁条接管增加离线回归测试。
- 在 `FIX_SUMMARY.md` 记录行为和验证结果。

## 非目标

- 不调整磁导航后退速度、末端磁条完成阈值或充电流程。
- 不改变 GPS 无效、导航超时和位置恢复失败的现有处理。
- 不改变磁条传感器消息格式。

## 验收标准

- GPS 相关进仓阶段收到连续两帧非零磁条信号后切换到 `LOADING_DIRECT_BACKWARD`。
- 磁条接管时轮速为零，下一次状态机执行沿用磁导航进仓流程。
- 单帧信号或信号中断不会触发接管。
- 现有磁导航和充电门控测试保持通过。
