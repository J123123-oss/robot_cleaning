# 桥架入口最小转角接入设计

## 意图

清扫区域结束点连接桥架入口时，若车体前进对准入口需要较大的原地转向，机器人容易在清扫区域末端产生不必要的横向偏移。对 YAML 中名称以 `bridge` 开头的区域，以该区域的首个航点作为桥架接入点，从前一清扫区域末点经所有过渡点接入时比较前进和倒车的最小车体转角。当前进转角超过 90° 时选择倒车接近，抵达入口后按入口航点的原始航向完成转向，并以前进方式通过桥架。

## 目标

- 保留普通清扫航段、跨文件衔接和最终返仓的现有前进行为。
- 复用现有区域名称链路。规划器将 YAML `name` 写入路径文件的 `#区域名` 注释，导航加载后保存到 `waypoint_areas`。
- 倒车接入使用与普通直线航段相同的 Stanley 几何、基础轮速、到点判定和近点减速。
- 到达桥架入口后仍执行该航点的最终航向校准，下一桥架航点使用前进输出。
- 保留定位可信度、电子围栏、IO 方向保护、停车确认和暂停恢复规则。

## 非目标

- 不改变桥架区域的路径点位置和航向数据。
- 不让所有航段自动选择前进或倒车。
- 不让倒车直接穿过整段桥架。
- 不修改最终返仓点的返仓策略。

## 约束

- 桥架区域名称采用大小写不敏感的 `bridge` 前缀匹配，例如 `bridge-2-3`。
- 桥架接入段从桥架区域之前的清扫区域末点开始，经该区域生成的 `_mid` 过渡点，到桥架区域首点结束。无过渡点时从清扫区域末点直接到桥架首点。
- 前进和倒车方位角相差 180°，前进转角小于或等于 90° 时保持前进，超过 90° 时选择倒车。
- 倒车接入时，Stanley 的路径几何仍表示当前过渡航段的前进方向，控制航向使用车体航向加 180°，输出左右轮交换以保持现有底盘运动方向约定。
- 入口到点后使用当前航点的 `get_path_heading()` 完成最终校准。航向校准成功后切换下一航点并清除桥架接入方向状态。

## 方案

### 方案一：显式新增路径段元数据

在路径文件中加入专用桥架接入字段，再由导航解析。语义最完整，但需要同步修改路径格式、规划器、导航、路径回放和已有路径兼容逻辑。

### 方案二：使用已有区域名称，选择桥架区域首点

沿用 YAML 区域名到路径文件区域注释再到 `waypoint_areas` 的现有链路。导航仅识别 `bridge` 区域的首个航点，计算最小转角并保存该接入段方向。该方案不改变路径格式，兼容已经生成的带区域注释路径，改动集中。

### 方案三：根据所有航点的几何方位自动选择倒车

不依赖区域名，对每个新航段都比较前进和倒车转角。实现简单，但会改变普通清扫和跨文件衔接的运动语义，也无法表达“只有桥架入口允许倒车”。

采用方案二，因为现有路径已经保留了区域名称，且需求边界由 YAML 的 `bridge` 命名明确给出。

## 行为流程

1. 到达清扫区域末点后，在开始该点的最终航向校准前，识别后续连续 `_mid` 点和桥架区域首点，并比较进入接入段的前进和倒车转角。
2. 当前进转角不超过 90°，保存 `FORWARD`，沿现有 Stanley 输出前进；超过 90° 保存 `BACKWARD`，清扫末点及中间点的最终校准目标使用其原航向加 180°。
3. 倒车时使用正向路径几何计算 Stanley，再交换左右轮输出形成倒车。方向贯穿全部过渡点直到桥架入口，不因密集点切换重复选择。
4. 倒车过程中复用现有距离阈值、连续可信定位样本确认、近点减速和安全停车。
5. 到达桥架入口后停止，按入口航点原始航向完成最终校准。
6. 校准成功后进入桥架区域的下一个航点，清除接入方向状态，按普通前进航段执行。
7. 暂停、AUTO 门控或进度恢复进入接入段时，必须保持或安全重建方向，不能先按前进航向旋转；不能可靠识别完整接入段时停车。

## 验证

- 区域名解析能识别 `bridge-2-3`，普通区域不触发。
- 前进转角 90° 时保持前进，超过 90° 时选择倒车。
- 倒车接入输出为前进输出的左右轮交换结果，目标航向为方位角加 180°。
- 倒车接入进入 0.10 m 后仍要求连续 3 个新的可信样本。
- 桥架入口校准完成后下一目标不再继承倒车方向。
- 现有普通航点和首点接入回归测试保持通过。
